# 0007: App framework: Preact, Vite, hand-written service worker

Date: 2026-10-22. Status: accepted.

## Context

`app/` is the PWA from docs/PLAN.md §6 (issue #31). It must install on a phone, work offline for
read views, stay small enough to load fast on a poor connection, and be readable as plain
TypeScript by a small team. The API client will later be generated by harness `client-ts`.

## Decision

- **Preact** (10.x, exact pin) with TypeScript and **Vite**. Preact keeps the React mental model at
  about 4 KB; the app needs no router or state library, so none is added.
- **Hash routing** (`#/journal/<id>`): the app is a static bundle with no server-side routes.
- **Hand-written service worker** in `app/public/sw.js` instead of a plugin. It caches the shell and
  GET read views only. API responses are cached per credential (the cache name carries a SHA-256 of
  the Authorization header) and cleared on sign-out. POST, reversals and bill matches are never
  cached or queued, and the UI says `offline: posting needs the server`.
- **Self-hosted fonts** from `@fontsource` (Source Sans 3, Source Code Pro), pinned exactly.
- **Npm with a committed lockfile**; every dependency is pinned to an exact version.

## Consequences

- Client functions are hand-written from the registry until the OpenAPI document carries full
  schemas; they are one function per command so the generated client can replace them without
  touching screens.
- Vitest covers the client, money and balance logic; Playwright covers the connect → post → reverse
  flow against a local fake API.
- Lighthouse and axe checks are not in CI yet; they belong with issues #52 and the acceptance
  criteria of #31.
